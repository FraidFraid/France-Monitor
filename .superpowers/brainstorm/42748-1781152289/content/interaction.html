Interaction heatmap → liste d'articles

Quand l'utilisateur clique sur une cellule de la heatmap (ex: "Securite, 8 juin"), que se passe-t-il ?

A

Filtre la liste existante

Cliquer sur une cellule applique automatiquement les filtres categorie + jour dans l'UnderMapNewsFeed en dessous. Les chips de filtre existants se mettent a jour. Re-cliquer = reset. La liste reste le meme composant, alimentee par /api/news?since=...&category=....

Flow
Clic sur cellule "Securite / 8 juin"
↓
8 juin 2026 × Securite ×
↓
Liste d'articles filtres (meme UnderMapNewsFeed)

+

  • Reutilise 100% l'UI existante
  • Zero nouveau composant de liste
  • Coherent avec le mode Live

-

  • Besoin d'etendre les filtres existants (date precise)
B

Detail inline sous la heatmap

Cliquer ouvre une zone de detail dans le widget heatmap lui-meme (comme le SituationHistoryPanel fait deja). Liste compacte des articles de cette cellule, sans toucher au news feed en dessous.

+

  • Le news feed live reste independant
  • Pattern deja utilise (SituationHistoryPanel)

-

  • Espace reduit pour la liste d'articles
  • Duplique du code de rendu d'articles
  • Pas de recherche texte dans le detail

Recommandation : Option A — filtrer la liste existante. C'est plus puissant (recherche, filtres croises), reutilise l'UI existante, et evite de dupliquer le rendu d'articles.
