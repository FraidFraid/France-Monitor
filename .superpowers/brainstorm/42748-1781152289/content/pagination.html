Chargement des articles historiques

En mode historique, une requete filtree peut renvoyer des centaines d'articles. Comment les charger ?

A

Bouton "Charger plus" (cursor-based)

Charge les 50 premiers articles. Un bouton en bas de liste charge les 50 suivants (append). L'API utilise un curseur (dernier publishedAt) pour la page suivante. Simple, previsible, pas de scroll piege.

+

  • Controle utilisateur explicite
  • Leger en memoire
  • Trivial cote API (WHERE publishedAt < cursor)

-

  • Un clic de plus pour voir la suite
B

Infinite scroll

IntersectionObserver sur un sentinel en bas de liste. Charge automatiquement la page suivante quand l'utilisateur approche du bas.

+

  • Fluide, zero friction

-

  • Peut charger trop en arriere-plan
  • Perte de position au retour
  • Plus de code (observer + cleanup)
C

Tout charger (limit 500)

Comme le mode Live actuel : une seule requete avec limit=500, filtre cote client. Pas de pagination.

+

  • Zero complexite pagination
  • Coherent avec le mode Live

-

  • Peut rater des articles au-dela de 500
  • Requete initiale plus lourde

Recommandation : Option A — "Charger plus" avec curseur. C'est le bon compromis : leger, explicite, et extensible. Le mode Live peut rester sur limit=500 (articles recents), le mode Historique utilise la pagination.
